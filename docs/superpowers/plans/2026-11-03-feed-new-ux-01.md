**Goal:** Reconstruire l'écran de composition d'une publication sur les trois
paliers, de sorte qu'il ne propose que ce qui fonctionne de bout en bout et
qu'aucun fichier choisi ne disparaisse en silence.

**Architecture:** Une page serveur mince (`page.tsx`) qui déclare le `viewport`
et monte un écran client ; un shell qui réutilise le chrome citoyen réel
(navigation desktop, rail medium, en-tête et barre basse mobile) ; un écran qui
assemble des sections de présentation ; deux hooks qui portent toute la
logique — `use-new-post-draft` (état du brouillon) et
`use-new-post-publication` (envoi, reprise, création). Sens des dépendances :
`page → shell → écran → sections` et `écran → hooks → lib/api`.

**Tech Stack:** Next.js 15 App Router · React 18 · TypeScript strict ·
Tailwind · Vitest 4 + Testing Library (jsdom) · Playwright (local, hors CI).

**Spec:** [`../specs/2026-11-03-feed-new-reconstruction-design.md`](../specs/2026-11-03-feed-new-reconstruction-design.md)

## Global Constraints

- **Breakpoints** : `lib/layout/feed-breakpoints.ts` fait foi — mobile ≤ 639,
  medium 640–1023,98, desktop ≥ 1024. ⛔ Ne pas réintroduire de seuil ad hoc.
- **Limites** : 2200 caractères · 10 médias · 20 Mo par fichier · types
  `image/jpeg`, `image/png`, `image/webp`, `video/mp4`, `video/webm`.
  Ces valeurs viennent de `@yunicity/utils` — ⛔ jamais réécrites en dur.
- **Débit serveur** : 60 envois/h par compte, 120/h par IP. Le message 429
  existe (`COMPOSER_MEDIA_RATE_LIMITED`).
- **Couleurs** : tokens `yunicity-*` uniquement. ⛔ Pas de gradient, pas de
  `backdrop-blur`, pas de hex ad hoc *(rule 14 §0)*.
- **Cibles tactiles** : toute commande ≥ 44 × 44 px de zone d'interaction.
- **Microcopie** : français, courte, orientée action. Une seule action primaire
  par écran.
- **TypeScript** : `strict`. ⛔ Pas de `any`, pas de `as unknown as`, pas de
  `@ts-ignore`.
- **Taille de fichier** : < 200 lignes *(`frontend-next-expo`)*.
- **À ne pas casser** *(acquis `MEDIA-MULTI-PHOTO-01`)* : `multiple`, aperçus
  de tous les fichiers, envoi en boucle, `media_urls` envoyé et stocké,
  plafond 10, verrou anti double-publication.
- **Commandes** depuis `frontend/apps/web/` :
  `pnpm vitest run <chemin>` · `pnpm typecheck` · `pnpm lint`.

## Review Focus

Cinq entrées que la spec implique sans qu'aucune tâche ne les exerce
spontanément. Chaque ligne a reçu son test dans la tâche propriétaire.

1. **Fichier sans type MIME renseigné** (partage iOS, certains sélecteurs
   Android) : le type est tranché par l'extension ; si l'extension ment, le
   serveur refuse — le message doit être attribué **à ce fichier**, pas au lot.
   → Tâche 4, étape 1.
2. **Deux sélections successives qui franchissent le plafond** (6 puis 6) :
   les 10 premiers restent, les 2 derniers sont **nommés**, rien n'est perdu en
   silence. → Tâche 2, étape 7.
3. **Sélection ou retrait pendant un envoi en cours** : les rangs ne se
   désynchronisent pas, et un fichier ajouté après le début d'une tentative
   n'est pas envoyé par cette tentative. → Tâche 4, étape 9.
4. **429 au milieu du lot** : message de débit, médias déjà envoyés conservés,
   réessai possible sans tout renvoyer. → Tâche 4, étape 5.
5. **Texte composé uniquement d'espaces** : `Publier` reste inactif — un
   `trim()` vide n'est pas un texte valide. → Tâche 2, étape 9.

```python
def _corps(cle: str, body: str = "Bonjour Reims") -> dict:

@pytest.mark.asyncio
async def test_replay_same_key_same_content_returns_same_post(
    auth_client: AsyncClient,

    """La réponse s'est perdue : le client rejoue, il ne doit PAS créer un doublon."""
```

```python
# backend/app/services/post_idempotency.py — créé
"""Empreinte de contenu d'une tentative de publication (FEED-NEW-UX-01).

Calculée SERVEUR, sur le payload déjà validé : le client n'envoie que sa clé.
Deux tentatives portant la même clé sont « le même contenu » si et seulement si
cette empreinte coïncide.
"""

import hashlib
import json

from app.schemas.post import PostCreateRequest


def compute_request_fingerprint(payload: PostCreateRequest) -> str:
    materiel = {
        "body": payload.body,
        "media_urls": [
            {"url": item.url, "media_type": item.media_type} for item in payload.media_urls
        ],
        "post_format": payload.post_format.value if payload.post_format else None,
        "visibility": payload.visibility.value,
    }
    canonique = json.dumps(materiel, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
    return hashlib.sha256(canonique.encode("utf-8")).hexdigest()
```

`PostCreateRequest` gagne `client_request_id: uuid.UUID | None = None`.
`Post` gagne les deux colonnes, typées comme dans la migration.

- [ ] **Step 5 : Service — rejeu, conflit, et la course**

```python
# backend/app/services/post_service.py — dans create_post
if payload.client_request_id is not None:
    empreinte = compute_request_fingerprint(payload)
    existant = await self._posts.get_by_client_request(
        author_id=current_user.id, client_request_id=payload.client_request_id
    )
    if existant is not None:
        return self._replay(existant, empreinte)
    post.client_request_id = payload.client_request_id
    post.client_request_fingerprint = empreinte

try:
    await self._session.commit()
except IntegrityError:
    # Course : une requête simultanée a inséré la même clé entre notre
    # lecture et notre écriture. L'unicité est tenue par l'index, pas par
    # le test ci-dessus — qui n'est qu'un raccourci du cas courant.
    await self._session.rollback()
    if payload.client_request_id is None:
        raise
    existant = await self._posts.get_by_client_request(
        author_id=current_user.id, client_request_id=payload.client_request_id
    )
    if existant is None:
        raise
    return self._replay(existant, compute_request_fingerprint(payload))
```

```python
def _replay(self, existant: Post, empreinte: str) -> PostResponse:
    if existant.client_request_fingerprint != empreinte:
        raise AppError(
            status_code=409,
            code="POST_REQUEST_CONFLICT",
            detail="Cette publication a déjà été envoyée avec un contenu différent.",
        )
    return self._to_response(existant)  # 200, aucune création
```

⚠️ Le **201** reste pour une création ; le rejeu renvoie **200**. La route
doit donc **choisir son code** au lieu du `status_code=201` figé du décorateur.

```ts
const addFiles = useCallback((files: FileList | null) => {
  if (!files || files.length === 0) return;
  const acceptes: MediaDraft[] = [];
  const refuses: RejectedFile[] = [];

  for (const file of Array.from(files)) {
    if (medias.length + acceptes.length >= POST_MEDIA_MAX_COUNT) {
      // Nommer CHAQUE fichier écarté : un `break` muet perdait les suivants.
      refuses.push({ name: file.name, reason: POST_NEW_MAX_REACHED(POST_MEDIA_MAX_COUNT) });
      continue;
    }
    if (file.size > MAX_BYTES) {
      refuses.push({ name: file.name, reason: POST_NEW_TOO_LARGE(STORIES_MEDIA_MAX_MB) });
      continue;
    }
    const nature = composerMediaKindFromMetadata(file);
    if (nature === "heic") {
      refuses.push({ name: file.name, reason: COMPOSER_MEDIA_HEIC_NOT_SUPPORTED });
      continue;
    }
    if (nature === "unknown") {
      refuses.push({ name: file.name, reason: POST_NEW_INVALID_TYPE });
      continue;

      id: newMediaId(),
      file,
      previewUrl: URL.createObjectURL(file),
      mediaType: nature === "video" ? "video" : "image",
      status: { kind: "selected" },
    });
  }

  if (acceptes.length > 0) setMedias((current) => [...current, ...acceptes]);
  if (refuses.length > 0) setRejectedFiles((current) => [...current, ...refuses]);
```

```ts
const moveMedia = useCallback(
  (id: string, direction: "forward" | "backward" | "first"): number => {
    let nouvellePosition = 0;
    setMedias((current) => {
      const depuis = current.findIndex((item) => item.id === id);
      if (depuis < 0) return current;
      const vers =
        direction === "first" ? 0 : direction === "forward" ? depuis - 1 : depuis + 1;
      if (vers < 0 || vers >= current.length) {
        nouvellePosition = depuis + 1;
        return current;
      }
      const suivant = [...current];
      const [deplace] = suivant.splice(depuis, 1);
      if (!deplace) return current;
      suivant.splice(vers, 0, deplace);
      nouvellePosition = vers + 1;
      return suivant;
    });
    return nouvellePosition;
  },
  [],
);
```

```ts
  const router = useRouter();
  const [state, setState] = useState<PublicationState>({ kind: "idle" });
  // Verrou SYNCHRONE : `state` n'est pas encore appliqué quand deux clics
  // arrivent dans le même tick. Couvre le double-clic, RIEN D'AUTRE —
  // une réponse serveur perdue est un autre risque (voir §8 de la spec).
  const publishingRef = useRef(false);
  const controllerRef = useRef<AbortController | null>(null);
  const timeoutsRef = useRef<Set<number>>(new Set());
  const mountedRef = useRef(true);

  useEffect(() => {
    mountedRef.current = true;
    const echeances = timeoutsRef.current;
    return () => {
      mountedRef.current = false;
      controllerRef.current?.abort();
      controllerRef.current = null;
      for (const e of echeances) window.clearTimeout(e);
      echeances.clear();
      publishingRef.current = false;
    };
  }, []);

  const publish = useCallback(() => {
    if (publishingRef.current) return;
    if (!draft.canPublish) return;
    publishingRef.current = true;

    const controller = new AbortController();
    controllerRef.current = controller;

    void (async () => {
      try {
        // Instantané pris AVANT la boucle : un média ajouté pendant
        // l'envoi n'appartient pas à cette tentative.
        const lot = draft.medias;
        const restants = lot.filter((m) => m.status.kind !== "uploaded");
        let envoyes = lot.length - restants.length;

        /**
         * ⚠️ Les URL s'accumulent ICI, pas dans l'état.
         * `draft` est figé au rendu du clic : `draft.medias` ne verra jamais
         * les `markUploaded` de cette boucle. Lire l'état pour construire le
         * payload enverrait `media_urls: []`.
         * On AMORCE avec ce qui était déjà passé lors d'une tentative
         * précédente — c'est ce qui rend la reprise possible.
         */
        const transferes: PostMediaItem[] = lot.flatMap((m) =>
          m.status.kind === "uploaded"
            ? [{ url: m.status.url, media_type: m.status.mediaType }]
            : [],
        );

        for (const item of restants) {
          if (controller.signal.aborted) return;
          setState({ kind: "uploading", done: envoyes, total: lot.length });
          draft.markUploading(item.id);
          const echeance = window.setTimeout(
            () => controller.abort(),
            composerMediaUploadTimeoutMs(item.file.size),
          );
          timeoutsRef.current.add(echeance);
          try {
            const reponse = await api.uploadPostMedia(item.file, controller.signal);
            if (!mountedRef.current) return;
            // L'état sert l'AFFICHAGE de la vignette ; le tableau local sert
            // le PAYLOAD. Les deux sont nécessaires, pour deux raisons.
            draft.markUploaded(item.id, reponse.url, reponse.media_type);
            transferes.push({ url: reponse.url, media_type: reponse.media_type });
            envoyes += 1;
          } catch (erreur) {
            if (!mountedRef.current) return;
            const message = controller.signal.aborted
              ? COMPOSER_MEDIA_TIMEOUT
              : composerMediaErrorMessage(erreur);
            draft.markFailed(item.id, message);
            setState({ kind: "failed", mediaId: item.id, message });
            return;
          } finally {
            window.clearTimeout(echeance);
            timeoutsRef.current.delete(echeance);
          }
        }

        setState({ kind: "creating" });
        await api.createFeedPost(draft.buildCreatePayload(transferes));
        if (!mountedRef.current) return;
        setState({ kind: "done" });
        router.push("/feed");
        router.refresh();
      } catch (erreur) {
        if (!mountedRef.current) return;
        setState({ kind: "failed", mediaId: null, message: composerMediaErrorMessage(erreur) });
      } finally {
        publishingRef.current = false;
        if (controllerRef.current === controller) controllerRef.current = null;
      }
    })();
  }, [api, draft, router]);

  return { state, publish, submitting: state.kind === "uploading" || state.kind === "creating" };
}
```

```ts
/** 409 `POST_REQUEST_CONFLICT` : la publication existe déjà, contenu différent. */
function estConflitDePublication(erreur: unknown): boolean {
  return (
    typeof erreur === "object" && erreur !== null &&
    ("code" in erreur ? erreur.code === "POST_REQUEST_CONFLICT" : false)
  );
}
```
